# 3.5：官方 LoRA 气球定位微调

**结论：完成官方LoRA训练与留出对照，有离线提升，但不采用部署，不进入实飞。** 区域正确由41/55提升到48/55；可用框几何门由0/55提升到11/55，红色仅3/20，远低于预定70%预飞门。封存飞行部署保持原样。本轮于2026-10-27收尾，未达到3天预算上限，无追加训练或新飞行。

训练前方案及后续兼容性补记见 [PLAN.md](PLAN.md)；补记均在留出推理前完成。原始输出、数据与校验索引见 [evidence/README.md](evidence/README.md)。

## 1. 数据可行性

先纠正基数：3.4 的 `manual_annotations.json` 有 155 条可见性记录（30 可见、122 不可见、3 不确定），但只有 **8 个红色气球的人工坐标框**，不是 155 个框。其余可见蓝/紫帧没有可信坐标，不能直接充作坐标监督。

补标不需要新飞行。本轮从 3.3 九局官方对照归档提取 146 张原始相机 JPEG，严格按图像时间戳匹配既存的 YOLO 检测消息，得到 180 个框提议。逐张查看 19 张复核联系表（全画面与目标放大图），剔除一张红色边缘碎片误报蓝色的图像及该框；保留 145 张图像、179 个框。加入旧的 8 个人工框与 36 张已审查的指定色不可见 PNG。

| 用途 | 整局轮次 | 唯一图像 | 红/紫/蓝阳性问答对象 | 负例对象 | 问答条数 |
|---|---|---:|---|---:|---:|
| 训练 | r1 | 65 | 29 / 31 / 8 | 每色4，共12 | 160 |
| 验证、选检查点 | r2 | 65 | 20 / 31 / 13 | 每色4，共12 | 152 |
| 留出测试 | r3 | 59 | 20 / 26 / 9 | 每色4，共12 | 134 |

每个对象分别构造一条区域问答、一条坐标问答；同图多个颜色共用原始图像。**问答条数不是独立图像数；图像数也不是独立试验局数。** 按整局分组，精确图像 SHA256 不跨集合，避免相邻帧随机切分。各集合仍来自同一仿真场景，相似机位/背景和连续帧相关性没有消失；它们也曾用于旧开发分析，不能称为全新场景盲验。

样本选择边界：新增阳性来自旧YOLO可检测源帧，偏向清晰目标；负例来自旧候选机位，没有按飞行中的真实出现频率采样。这里的帧级正确率不能直接换算成实际每秒触发率或击球命中率。

标签质量边界：新增框是“旧 YOLO 提议 + 单 AI 视觉复核”，没有第二位独立人工逐像素描边；8 个旧红框约 ±4px。区域标签可直接视觉核对，框的几何指标仍受提议边界误差影响。蓝色训练阳性仅8个，本轮没有补足3.1蓝色正式验收缺口。

原始图像、标签、SHA256、来源归档成员、官方问答 JSON 都在 [evidence/README.md](evidence/README.md) 索引中，源图打包为 `evidence/dataset.tar.gz`。带框联系表只用于复核，绝不作为训练图像。

## 2. 输出粒度和控制边界

主任务使用完整原始图像，回答指定颜色的 `color + region`（left/center/right，按可见球体中心横向三等分）；不存在时两字段为 `none`。这是用户建议的低风险起点。

辅任务单独提问球体可见部分的紧致 bbox，坐标归一化为0–1000，不包含小车、绳子。每条问答只有一轮，不把标准区域答案喂给 bbox 问答。无外部切块，无运行时 YOLO/HSV/UE 真值修框。

现有 CSRT 初始化需要可信矩形，区域准确率提升本身不提供这个矩形。因此本轮预先规定：区域提升可以作为离线结果，但进入既有飞行链路必须同时通过坐标门。没有用粗分区中心伪造检测框，也没有更改 VisualServo 状态机、安全边界或封存控制结构。

若离线门通过，运行时计划使用 `PeftModel.from_pretrained(已有实例, 适配器)` 复用一个基座；图像定位启用适配器，任务文本/行为树生成用同一实例的 `disable_adapter()` 原始参数上下文，避免定位微调同时改变已验证的自然语言入口。定位问答始终使用完整源图，不能把本轮整图坐标监督直接套到旧分块提示词。该段是条件接入方案，尚未实现或验证，不能记为已部署。

## 3. 官方流程与训练配置

用户提供的修正版手册 SHA256、提取片段及官方源码快照见 `evidence/reference/`。官方仓库：<https://osredm.com/jiuyuan/CPM-9G-8B>，FM9G-V 分支固定提交 `7530eba39cf345d4991eb955ed7ef6665c8f58e9`。

该提交包含 `finetune.py`、`dataset.py`、`trainer.py` 和 `finetune_ds.sh`，**没有 `finetune_lora.sh` 文件**。本轮从手册第133段保留换行提取 LoRA 启动命令；原文脚本和执行版本的差异保留为 `reference/launcher.diff`，并非声称下载到了仓库中不存在的文件。

| 参数 | 采用起点 |
|---|---|
| 基座 | `/home/ubuntu/model/FM9G4B-V`，只读 |
| LoRA | r=64、alpha=64、dropout=.05（官方 Python 默认） |
| 目标正则 | 手册 q_proj/k_proj/v_proj/o_proj 正则 |
| 实际匹配约束 | 当前模型采用 q_a/q_b/kv_a/kv_b 命名，手册正则只匹配 o_proj；实测模块清单另存 |
| 视觉、语言 | tune_vision=true，tune_llm=false，use_lora=true |
| 其他可训练模块 | 官方脚本指定 embed_tokens、resampler、vpm；并非全模型仅训练低秩矩阵 |
| 优化 | 起点FP16，第0步dtype冲突后改BF16；ZeRO2、batch=1、LR=1e-6、weight_decay=.1、beta2=.95 |
| 输入 | max_length=2048、max_slice_nums=9（模型原生预处理，不是旧流水线16块逐块提问） |
| 预算调整 | 官方10000 steps上限，实际每200 steps验证/保存（实例中断后适配）；1000步后验证loss连续两次未改善0.005早停，24小时硬上限；保留2检查点，按验证loss选最佳，seed=3501 |
| 评估内存 | prediction_loss_only=true，避免保存整个词表logits |

手册原始上限是10000 steps、1000步验证、10个检查点；本轮保留步数上限，在实例中断后将验证/保存频率改为200步，检查点只留2个，并以验证loss早停和24小时上限限制预算。初稿拟1000步，实际启动前恢复官方上限，未执行过该短跑。完整差异均已保留，不把早停/日志/路径适配隐藏为“只改DATA”。不以留出测试选择检查点或修改提示词。

训练独立环境和输出目录：`/root/gpufree-data/tcei_lora35/`。推理 `demo` 环境不更新。GPU实机是L40（nvidia-smi 可见总显存 46,068 MiB），使用23GiB PyTorch分配器上限为CUDA上下文留余量，另记峰值；这是大显存卡限额实验，不能直接宣传为物理24GB显卡复现。

数据通路用官方预处理逐条检查：训练160+验证152，共312条问答均含真实图像、非空图像边界及监督token，未被2048长度截断。先前demo的NumPy1.23不支持官方 `np.hstack(..., dtype=...)`，隔离环境改为1.24.4；隔离Torch初次导入缺CUDA动态库，通过只在该venv内建立继承库链接解决。原始失败、成功检查和安装记录见 `startup_evidence.tar.gz`，没有修改demo或官方预处理源码。

随机性边界：seed=3501控制官方Trainer采样/训练；官方脚本在Trainer设种子之前创建LoRA初始矩阵，本轮没有额外改写这一顺序。因此不宣称从头重训逐位相同，最终检查点及散列用于复现本轮推理。

首次起跑在第0步因 `BFloat16 and Half` 失败：基座 `resampler.py:300` 强制特征为BF16，而手册加载FP16权重。未修改模型源码，以BF16重试（四个精度参数对称切换，ZeRO2自动对应）。原始异常和首次运行的脚本、参数/显存记录保留；尚无优化器更新，不能把它算成一轮有效微调。

第二次BF16起跑在首次优化器更新时触发23GiB分配器限额（申请额外2.42GiB），0个调度步完成。原始OOM记录保留。第三次使用派生的ZeRO2配置将优化器状态移到CPU，并保留官方PyTorch AdamW算法；官方原始JSON未改，差异见 `reference/deepspeed_cpu.diff`。此配置需要额外CPU内存，另记训练进程RSS。

第三次已实际更新226步，随后服务器失联；用户恢复原实例后，原PID不存在，尚无检查点。此段更新未进入最终模型，单独作为环境中断记录保留。第四次从基座重新开始，保存/验证周期统一为200步，1000步前不早停；只从含完整训练状态、匹配数据散列的检查点自动续跑。24小时训练硬预算跨重启累计，不重新计时。

## 4. 离线对照

训练前验证集基座：64个阳性、12个负例，区域正确49/64（红18/20、紫23/31、蓝8/13）；bbox几何门仅1/64，中心误差中位数93.11px。基座验证输入均经processor审计，152次调用全部含1张真实图像。该验证结果不替代最终留出对照。

### 4.1 公平对照与冻结判据

两模型使用同一隔离环境：Torch2.2.0、Transformers4.44.2、PEFT0.14.0、DeepSpeed0.12.3、Accelerate0.30.1、NumPy1.24.4；BF16，贪心解码，max_new_tokens=128、num_beams=1、原生slice上限9。基座先跑、退出释放GPU后再跑800步适配器。没有并发加载第二份模型。

每模型67个指定色对象、134次实际含图processor调用；59张唯一真实图像，来自r3六局旧试验（其中三局提供大部分阳性，另三局提供负例和3个手工框）。估计器只收到图像、指定色和样本身份，生成结果全部落盘后才连接标签计分。两问都用同一张完整原图、独立单轮；第二问没有收到标准区域或坐标答案。

几何门保持3.4定义：`IoU ≥ 0.5 且中心误差 ≤ max(8px, 标注框对角线×20%)`，非法JSON计失败。另算第一问确认指定色存在与第二问几何通过的交集，作为实际可提交CSRT的比例；本轮11个通过均在该交集中。

红色预飞门独立于紫蓝：区域≥85%、相对基座提升≥10个百分点（基座已≥85%则不得退步），交集几何≥70%且高于基座、4个红负例零错误。三色扩展另需整体区域≥85%、提升≥10个百分点、每色≥75%、区域负例错误≤1/12；整体交集几何≥70%、每色≥60%、红≥70%、bbox负例错误≤1/12。**留出结果出来后没有放宽门槛、重选检查点或修改提示词/解析器。**

### 4.2 留出结果

| 指定色 | 阳性数 | 区域完全正确：基座 → LoRA | 几何/两步交集通过：基座 → LoRA | 中心误差中位数px：基座 → LoRA |
|---|---:|---|---|---|
| 红 | 20 | 17/20 → 17/20（85.0%） | 0/20 → 3/20（15.0%） | 60.93 → 17.94 |
| 紫 | 26 | 22/26 → 25/26（96.2%） | 0/26 → 5/26（19.2%） | 130.29 → 12.71 |
| 蓝 | 9 | 2/9 → 6/9（66.7%） | 0/9 → 3/9（33.3%） | 92.76 → 24.60 |
| 合计 | 55 | 41/55 → 48/55（74.5% → 87.3%，+12.7个百分点） | 0/55 → 11/55（20.0%） | 102.59 → 18.95 |

中心误差只对可解析非空框统计：基座55个，LoRA49个（红19、紫22、蓝8），不能用该中位数隐藏6个失败。限定为同一49个可配对对象，基座中位数107.51px，LoRA18.95px，仍有改善。几何通过率的分母始终保留全部55个阳性。

12个负例：区域答案完全符合`none/none`的错误数3→2；独立bbox非空错误2→2，均来自蓝色。LoRA两次区域错误实际为`color=none, region=left`，是字段不一致，不能都称为目标误报；两步存在门均拒绝它们。基座实际可通过两步存在+非空框门的负例1/12，LoRA0/12。这不改变预先定义的原始问答质量门。

单次模型调用延迟中位数1.011s→0.795s，两问合计中位数2.238s→2.068s；这是离线推理时延，**不等于比赛用时收益**。两模型推理PyTorch峰值reserved分别约9.74/10.99GiB，训练资源另见§3。

|---|---:|---|---|

| 40px＜最大边≤80px | 19 | 16 → 18 | 0 → 4 |

## 5. 飞行验证与采用结论

**不采用，停止本轮；新正式试验0局。** 红色区域门通过，但几何仅15%，未达到70%；三色区域总分虽达87.3%且提升12.7个百分点，蓝色仅66.7%且负例错误2/12，三色区域门也未通过；总体几何20%同样未通过。因此没有实施运行时接入、窗口部署、红色3局或紫蓝扩展，不虚报`sprint_start_count`、击球成功率或总用时。

本次证据支持“官方LoRA流程能在这批同场景留出帧上改善坐标与部分区域回答”，不支持“已经能可靠初始化CSRT”或“多模态加分项通过”。现有65张训练图、蓝色8个阳性及单审提议框，只能作为种子集；后期过拟合、蓝色不均衡、精确框监督不足和手册正则仅匹配o_proj均为限制，不能凭本轮确定各自因果权重，也不能据此断言LoRA路线普遍不可行。

若以后单独批准继续，优先补独立复核框、蓝色/遮挡/边缘/不同车道机位与负例，按整局重新留出；在新训练前核对官方目标模块命名。当前不再加一版调参、不把粗分区中心伪装成CSRT框、不占仿真补飞行。正式部署继续使用原封存版本。

## 6. 合规和恢复
