## 3. 与旧审计相比发生了什么

参与审计的 61 个来源文件中，57 个保持原字节；变化的四个文件正是已恢复的 `bspline_opt` 文件，详见 [来源清单](evidence/source_manifest.json) 与上述比较记录。旧报告关于“规划器官方基线副本包含团队候选”的问题，在此次修复快照中已经消除。

另外按 Git 树逐项对照了 `official_baseline/` 与首次入库提交 `045155040198da0a0a19dcad14797fa17d6a45e4`：原有 1,527 个文件无缺失，1,523 个 Git blob 完全相同；另外四个文件仅有 LF/CRLF 差异，源码内容一致。新增的两个文件是边界说明 README 和局部换行属性文件。这说明它与**本仓库最初导入的快照**一致，不是对官方上游发行包或当前服务器版本的独立认证。

其余七项创新核对中的限制继续成立：安全恢复仍需区分官方悬停、团队单余量和最终双余量；ArUco 原始 84 帧仍未提供；命令兜底仍可能输出不合格候选；红区入场方向的归因需与坐标调整分开；紫区单参数调整不能外推为长期安全性；返航指标仍是设定点—机体距离；蓝球近距丢失条件默认仍为 `(1.0, 1.25]` 秒。基线恢复本身不会消除这些证据边界。

## 4. 服务器阶段的执行顺序与缺失条件

`official_baseline/` 是仓库源码快照；`baseline_tools/` 是启动、观察和记录工具，首次入库后加入了正式单局编排和更多记录功能。回退记录工具不能使服务器代码变成官方版，也可能失去现有实验编排入口。本次未擅自回退这些工具或删除其历史结果。

取得服务器连接并核实环境后，按以下顺序继续：

1. 只读检查服务器任务锁、最近实验时间和相关进程，确认共享实例空闲；读取运行源码、参数和编译产物的版本。
2. 备份当前运行版本并记录校验值，锁定可验证的官方对照。特别需要找到官方原始 `mission_once.py`、模型和提示词；仓库现有材料不能替代缺失的完整原始模型流程。
3. 按审计方案分别建立对照和候选。安全恢复是三版本对照；返航前视实验需要同一团队完整版本的开/关配对，不能把两组都简单覆盖成整套官方程序。
4. 编译、启动并核验当前实际加载的版本，然后串行执行实验并记录原始日志；每组结束检查结果和环境状态。

| 审计中的正式组别 | 最小计划 | 当前待补条件 |
|---|---|---|
| ArUco 回放与消融 | 同一组 84 帧、同一 62–82 窗口，原有 6 种配置 | 原始真实帧、窗口依据、OpenCV 环境 |
| 安全恢复三版本对照 | 官方悬停、团队单余量、最终双余量，每版本至少 5 个独立仿真局 | 可用服务器、当前状态与可验证的版本部署 |
| 返航前视对照 | 同一团队完整版本，关闭 / 0.6 m，交错各 5 局 | 可用服务器、完整候选版本、同色同场景条件 |
| 真实模型流程对照 | 官方原始流程与最新校验流程，20 类措辞，每类每版本至少 3 次 | 官方原始模型入口、同一模型权重/提示词/采样设置及可用推理环境 |

上述正式实验尚未执行。本机未发现已配置的 TCEI 连接环境变量或可用 SSH 配置入口；需要提供服务器登录方式或凭据文件路径后才能核实并操作服务器。
