# 3.3 第二轮回归协议（正式采样前冻结）

日期：2026-10-26；三色演示先单列，不进入以下回归分母。

- 封存基线与固定九格候选各 9 局，红/紫/蓝每组每色各 3 局。按颜色和轮次配对，交替先后顺序；每局独立新鲜三球场景。候选若修改，之前采样保留但不混入同一固定版本回归。
- 必须先完成三色各 1 局的窗口/控制证据：真实传图、所需色语义选择、所选框被消费、执行控制与选择一致。此门检验识别参与控制；命中与否交给回归单独比较，不能把演示一局成功外推成功率。
- 主指标为物理目标命中、误击/额外删球、各阶段新故障、总飞行用时及击球段用时。保留官方观察器原始字段，不把 BT SUCCESS、Timeout/ForceSuccess 或空 hit 状态当成命中。
- 独立只读观察器记录完整任务关键日志/控制，击球阶段约 10 Hz 原始 RGB 及真实 X11 窗口截图。算法仅可读相机和模型自身状态，不可读 UE 真值/判定文件。
- 为免测量工具污染，本轮**不在飞行中发送 GC**。每局正式 runner 完成且 PX4 确认解除武装后，才发送一次 GC，并记录同 UE 实例前后两次对象列表。Actor 删除证据与目标色破裂/贴近消失帧交叉核对；缺颜色或时序证据的条目标为 unknown，不排除出分母。
- 评估工具修订（03:35，正式回归尚未开始）：红色演示的飞前对象载荷查询虽已关闭接收线程，飞后 GC 仍使 UE 在 `ARflyHUD::processReqDataLoop` 崩溃。保留原崩溃日志及缺失物理结果，不把它算成算法飞行失败。**取消所有飞前/飞中 `reqObj`**。正式回归只在飞行结束、解除武装、GC 及两次对象列表已保存后，对仍存活 Actor 固定 15 秒查询位置，再完整重启 UE，绝不复用该 UE 飞行或再次 GC。依据已验证红 y=+2.1、紫 y=-2.1、蓝 x=5.6 车道给存活 ID 标色，从三色全集减去存活色判断删球。颜色来自车道标定而非 SDK 颜色属性；缺响应或场景不一致标 unknown。不把 ID 跨实例复用。结果只写 `evaluation_mapping.json`，不发布 ROS、不被模型/控制读取。两组均使用该飞后测量流程。
- 采用条件：每色候选的已确认命中数不低于配对基线，没有新的系统性失败模式；总用时中位数增加不超过 max(10 秒, 基线中位数的 10%)。该容差预先用于识别明显退化，不是统计等效证明。9 局小样本不能证明比赛现场可靠性不变。
- 不补删失败局、超时和不利样本；环境异常与模型异常保留并单列，若补跑须记录原局和原因。若明显退化，报告失败原因和不采用建议，恢复封存基线。
