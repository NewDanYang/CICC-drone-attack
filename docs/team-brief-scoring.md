## 二、任务一：九格多模态大模型目标识别（优先做这个）

### 为什么说这是明确可拿的分

比赛规则（`打击.pdf` 第 4.3 节加分项）：**使用九格多模态大模型做目标识别得 10 分，
未使用得 0 分**。这和"九格大模型语义解析自然语言指令"（必选项，不用直接判 0 分）
是**两件不同的事**——语义解析已经在用（`mission_once.py`），但多模态视觉能力完全没用上。

**证据**：`/home/ubuntu/model/mission_once.py` 里所有 `model.chat(...)` 调用，
`image` 参数永远是 `None`：

```python
result = model.chat(image=None, msgs=msgs, tokenizer=tokenizer, ...)
```

大模型从头到尾只处理文字，从没真正"看"过一张图。这就是你要补的缺口。

### 现有感知链路（先读懂，再决定怎么接入）

- 气球颜色识别：`/home/ubuntu/catkin_ws/src/object_det/scripts/det_color.py`
  （YOLO + HSV，发布到 `/objects`，`common_msgs/Objects`）
- 二维码识别：`/home/ubuntu/catkin_ws/src/mission_pkg/scripts/aruco_detect_node.py`
  （经典 CV，发布到 `/aruco/detected_id`）

这两个都是经典 CV，不是多模态模型。你的任务是让九格多模态模型**真正参与**
其中至少一个判断点。

### 实现思路（你来定细节，这里给约束和方向）

1. 截取相关区域的图像帧（气球检测框、或二维码检测框附近的画面）
2. 转成 `PIL.Image`，调用 `model.chat(image=<PIL图像>, msgs=[{"role":"user","content":[image, 提示词]}], ...)`
3. 让模型的回答参与一个**实际会影响任务执行**的判断（比如确认气球颜色、
   确认识别到的二维码内容），而不是跑一下但结果没人用——那样等于没做

### 硬约束（违反会被判 0 分或扣分，务必遵守）

- **不能用这个接口一次性完成多个任务阶段**。规则原文：
  "不允许人工编写一次完成多个阶段任务的接口，让大模型直接调用"，
  典型反例是"写一个能飞完全程的接口"。你的多模态调用范围必须严格限定在
  "识别"这一个判断点，前后的飞行控制仍然走现有的分步行为树节点。
- **必须有可视化窗口展示识别结果**（规则要求，否则该阶段扣 5 分）。
  参考 `aruco_detect_node.py` 里 `/aruco/debug_image` 的做法。
- 现场评审会要求你展示"大模型到无人机控制量的完整传输环路"，并可能要求
  用 `rostopic echo /mavros/setpoint_raw/*` 现场验证控制数据在变化
  （`打击.pdf` 图 3-3）。设计的时候就要考虑这一点，不要做成黑箱。
- 禁止在源码里写死任何预设位置/轨迹点（"指点飞行"，查到直接本阶段扣 5 分）。

### 验证要求
