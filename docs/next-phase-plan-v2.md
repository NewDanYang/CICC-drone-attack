## 新信息：预设点位问题已解决

直接问了主办方："官方 demo 在气球区的代码中写了固定的 approach_pos、goal 和 yaw 角度，
我们是否可以修改这个固定的坐标值，而不是说新加固定点"。

**回复：这个是没问题的，不过可能随之也浪费些时间。demo 里面不是最优方案。**

这解决了 v1 里"待向主办方确认"第 1 条。结论：
- 沿用或手调官方 demo 自带的气球区坐标，**不算违规**，不需要为了合规把 `approach_pos`/`goal`
  改成运行时感知计算。
- 但官方自己也说这套坐标不是最优——所以调它更多是为了**提高可靠性**（减少误击、减少冲出场地），
  不是为了规则合规。这改变了后面 1.x 系列任务的技术方向，见下文。

## 优先级调整：先保基础分，加分项全部暂停

创新文档 1–3/节点）全部暂停**，等基础分稳定后再捡。第二部分的规则合规工作里，只保留
**直接保护基础分**的几项，其余也往后放。

## 第一部分（唯一当前优先级）：气球阶段稳定过关

**目标不变**：红紫蓝各 ≥3 局、三球全在场、零误击、零"同局少两只球"、边界触发 ≤1/9。
**新增两项，替代原计划里"只改 SPRINTING"的 1.3 思路**：

| # | 任务 | 验收 |
|---|---|---|
| 1.5 | 把"近距离/面积突增即刹车"的判据从 SPRINTING 扩展到 **APPROACHING 阶段**（1.3 的判据逻辑基本可以照搬，改成在 APPROACHING 分支里也检查），覆盖 1.2 发现的"未冲刺就已贴近"的 5/9 情况 | 和 1.1 基线对比：越界 ≤1/9，误击不高于 1.1 的 2/9（这次目标是不变差，不是立刻归零） |
| 1.6 | **误击根因排查**：现在确认可以自由调整三个区的 `approach_pos`/`goal`/`yaw`（不违规），排查误击是不是因为接近轨迹离非目标球太近、或 `TargetTracker` 的 `confidence_threshold=0.8` 不够严导致认错球。先用 1.1/1.3 已有的试验数据做离线分析（哪几局误击、误击时无人机在场景里的位置、离哪个非目标球最近），不需要先上服务器 | 给出误击的具体触发条件假说，附证据；如果假说成立，给出修复方向（调整接近路径、收紧识别阈值，或两者都做） |
| 1.7 | 根据 1.6 的结论改代码（可能是调整坐标、可能是调整识别阈值、可能两者都要），**每次只改一个变量**，重新跑三色各 ≥3 局验收 | 三球全在场、零误击、零"少两只球"、边界触发 ≤1/9，三项同时满足才算过 |

**完成标准和 v1 一致**：三球全在场时每色 ≥3/3、零误击、边界触发 ≤1/9，每局记录用时。
